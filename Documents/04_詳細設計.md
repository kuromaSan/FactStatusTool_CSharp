# FactStatus 詳細設計・実装手順

## 進め方

各工程は「仕様確認 → 実装 → 自動テスト → 手動確認 → 達成内容一覧の更新」の順で実施する。データ形式を変更する工程では、作業前に `Documents/` をコピーして退避する。

## 1. 環境とベースラインの確認

1. `00_環境構築.md` のコマンドで restore、build、test、UI起動を実行する。
2. 使用SDK、実行したコマンド、失敗内容を記録する。
3. 既存の `Documents/IDPatternRules.json` と `Documents/RelationalData.json` を読み、サンプルデータの構造を確認する。
4. 成功した項目を `03_達成内容一覧.md` の「完了」に更新する。

完了条件: ビルド・テスト・UI起動の可否と、失敗した場合の再現手順が明確であること。

## 2. ドメインルールの確定

1. 各 `IdTypeEnum` の必須属性と作成可能な親を `IDPatternRules.json` と照合する。
2. `CreateEntity`、`DeleteEntity`、`MoveEntity`、`CopyEntity`、`GroupEntity` の事前条件・事後条件をテストケースとして列挙する。
3. 不正なID種別、存在しないID、循環する親子関係、重複グループ登録の扱いを決める。
4. `FactStatusPolicy` と `FactStatusAggregate` に検証を実装し、例外メッセージを利用者が判断できる内容にそろえる。
5. 正常系・異常系のxUnitテストを追加する。

完了条件: 操作ごとの制約がテストで表現され、制約違反時にデータが部分更新されないこと。

## 3. JSON入出力の完成

1. `JsonDto` / `JsonDtoBuilder` が全エンティティ、属性、親子リンク、グループリンクを変換することを確認する。
2. JSON保存 → JSON読込 → 再保存の往復テストを追加する。
3. リレーショナル形式JSONについても同じ往復テストを追加する。
4. ファイル不存在、形式不正、ID重複、参照先不存在のエラーを検証する。
5. 形式を変更する場合は互換性方針と移行手順を記録する。

完了条件: サンプルデータを読み込み、内容と関連を保ったまま保存・再読み込みできること。

## 4. Markdown入出力の完成

1. 各エンティティのMarkdown表現を決める。最低限、ID、タイトル、説明、固有属性、親子リンク、グループリンクを表現する。
2. `MarkdownDtoBuilder` が上記のMarkdownを生成するようにする。
3. `MarkdownRepository.LoadMarkdown` を実装し、単体ファイルをDTOへ変換する。
4. ルート配下を再帰走査して、Markdownツリーから `FactStatusAggregate` を復元する処理を実装する。
5. ファイル名、相対リンク、ディレクトリ名の規約を定義し、Windowsパスと区切り文字の違いを吸収する。
6. 単体・ルート・往復のテストを追加し、既存の `Documents/` サンプルで手動確認する。

完了条件: Markdownツリーの保存と読み込みを往復して、エンティティと関連が復元されること。

## 5. Avalonia UI の実装

1. `IFactStatus` / `IFactStatusCrafter` を通じてUIがドメイン層を呼び出せるようにし、DIの構成を決める。
2. メイン画面を「ファイル操作」「ツリー」「詳細」「操作・集計」の4領域に分ける。
3. ツリーにDocumentからの親子構造を表示し、選択IDを `FactStatusMain.SelectIdValue` に反映する。
4. 選択要素に応じた編集フォームを表示し、作成・編集・削除・移動・複製・グループ化を実装する。
5. 読み込み・保存先の選択、未保存変更の確認、例外メッセージの通知を実装する。
6. 成功・失敗件数と失敗内容を表示する集計ビューを追加する。

完了条件: 利用者がUIだけでサンプルを読み込み、編集し、保存して再度開けること。

## 6. テストと受入確認

1. ドメイン、JSON、Markdown、UIの主要シナリオをテスト一覧にする。
2. テストを実行し、失敗は原因・対応・再実行結果を記録する。
3. 以下を手動受入確認する。

   - 新しいSubjectからAchievement、Evidence、Result、Recordを作成できる
   - EvidenceとRecordの成功／失敗を設定し、集計が変化する
   - Todo、Schema、Groupを作成し、関連を参照できる
   - JSONとMarkdownで保存後に再読み込みできる
   - 不正な操作で既存データが壊れない

4. 残課題と既知の制約を `03_達成内容一覧.md` に更新する。

完了条件: 主要シナリオの自動テストと手動受入確認が完了し、残課題が明文化されていること。
