# FactStatus 基本設計

## 目的

FactStatus は、主題に対する達成・証拠・結果・記録を関連付け、達成状況を追跡・保存・参照するツールとする。構想や実施手順も主題・証拠に紐付けて管理する。

## 利用者が行うこと

- ドキュメントのルートを読み込み、対象の主題を選択する。
- 達成、証拠、結果、記録、手順、構想を作成・編集・削除・移動・複製する。
- 証拠・記録の成功／失敗を記録し、件数や失敗内容を確認する。
- データをJSON、リレーショナル形式JSON、Markdownツリーとして保存・読み込みする。

## 概念モデル

主要な親子関係は次のとおりとする。

```text
Document
└─ Subject
   ├─ Achievement
   │  ├─ Evidence
   │  │  └─ Result
   │  │     └─ Record
   │  └─ Todo
   └─ Schema

Evidence ── Todo / Schema
Group ───── Subject / Achievement / Evidence / Todo / Schema
```

| 要素 | 役割 |
| --- | --- |
| Document | ドキュメント全体のルート |
| Subject | 管理対象となる主題 |
| Achievement | 主題に対して目指す、または得た達成 |
| Evidence | 達成を裏付ける証拠。成功状態を保持する |
| Result | 証拠に対する結果。引数・アサーションを保持する |
| Record | 結果の実行・確認記録。日時、確認者、成功状態を保持する |
| Todo | 実施手順・作業項目 |
| Schema | 経験、評価、仮説、目標を表す構想 |
| Group | 複数要素を横断的にまとめる集合 |

## システム構成

| 層 | プロジェクト | 責務 |
| --- | --- | --- |
| ドメイン | `FactStatus.Domain` | エンティティ、値オブジェクト、ポリシー、永続化、ユースケース |
| UI | `FactStatus.UI` | Avalonia による操作画面、ドメイン層の呼び出し |
| テスト | `FactStatus.Domain.Test` | ドメイン処理と永続化処理の自動テスト |

ドメイン層では `FactStatusMain` を操作窓口とし、`FactStatusPolicy` がエンティティ操作・集計・入出力を統括する。データ全体は `FactStatusAggregate` として扱い、IDごとの辞書と親子・グループのリンクで関連を表現する。

## 入出力設計

| 形式 | 用途 | 想定パス |
| --- | --- | --- |
| JSON | FactStatus 全体の保存・復元 | `Documents/*.json` |
| リレーショナル形式JSON | エンティティ・属性・辺を分離した保存 | `Documents/RelationalData.json` |
| Markdown | 人が閲覧・編集しやすいドキュメントツリー | `Documents/` 配下 |

ID種別・属性・関連のルールは `Documents/IDPatternRules.json` を基準とする。Markdownのファイル名・見出し・リンク形式は、このルールと整合させる。

### 保存方針

- 書き込み可能モードでは、エンティティの作成・編集・削除・関連変更をデフォルトで自動保存する。
- 自動保存の対象は、現在開いているデータ形式および保存先とする。
- 保存中・保存済み・保存失敗をUIで明示し、保存失敗時は再試行または保存先の変更を可能にする。
- 利用者はファイルメニューから手動保存および名前を付けて保存も実行できる。

## 品質方針

- ID種別、親子関係、グループ化の制約をドメイン層で検証する。
- 保存後に再読み込みでき、主要な属性と関連が失われないことをテストする。
- UIでは破壊的な操作の確認、エラー内容の表示、未保存変更の扱いを明確にする。
- 既存の `Documents/` データを壊さずに移行・保存できることを優先する。
