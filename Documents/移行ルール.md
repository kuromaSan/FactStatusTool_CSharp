# 文書移行ルール

## 目的

旧形式の設計書を `Subject` を起点とする文書構造へ分割し、内容・手順・検証根拠・採用理由を追跡できるようにする。
移行では内容を省略せず、旧文書を削除する前にすべての参照先が新しい構造で確認できる状態にする。

## 文書種別と配置

| 種別 | 配置する内容 | 親子関係 |
| --- | --- | --- |
| `Subject` | 主題の目的、前提、企画内容 | 文書構造の起点 |
| `Achievement` | 実装・作業として何を行うか | `Subject` の企画実装から参照 |
| `Evidence` | 実装できたことを何で確認するか | `Achievement` の実装証拠から参照 |
| `Todo` | 実行手順 | `Achievement` または `Evidence` から参照 |
| `Schema` | なぜ採用するか、背景・評価・仮説・目標 | `Subject` または `Achievement` から参照 |
| `Result` | 証拠に対する引数、表明、記録一覧 | `Evidence` の証拠結果から参照 |
| `Record` | 確認日時、確認者、OK/NG、記録内容 | `Result` の記録一覧から参照 |

`Record` と `Result` は見出しとリンク構造のみを既存テンプレートから読み取れる状態であり、どの旧内容を配置するかの判断基準は未定義である。説明を受けるまでは、これらに旧内容を推測で移さない。

## 旧文書の内容の振り分け

| 旧文書の内容 | 移行先 |
| --- | --- |
| 目的、対象、前提条件、対応環境 | `Subject` の「企画内容」 |
| 実施する作業、機能、設定 | `Achievement` の「実装内容」 |
| コマンド、操作順、チェックの手順 | `Todo` |
| 成功条件、確認観点、チェックリスト | `Evidence` |
| 採用理由、比較、背景、仮説、目標 | `Schema` |
| 実行時の引数・表明・確認履歴 | `Result` / `Record`（基準が定義された後） |

基本設計、画面設計、達成内容一覧、詳細設計を移す場合も、見出し単位・表の行・コードブロック・チェックリストをこの表に従って振り分ける。

## 移行手順

1. 旧文書の見出し、表、コードブロック、チェックリスト、既存リンクをすべて洗い出す。
1. 主題ごとに `Subject` の README を作成し、「企画内容」「企画実装」「企画構想」を記載する。
1. 作業ごとに `Achievement` の README を作成し、実装内容・証拠・手順を分離する。
1. 企画実装から `Achievement`、実装証拠から `Evidence`、実装手順から `Todo`、採用理由から `Schema` へリンクする。
1. `Evidence`、`Todo`、`Schema` のリンク先 README を同時に作成し、元の説明・コマンド・表を必要な文書へ移す。
1. 旧文書の各項目に対応する新規文書があること、すべてのローカルリンクが解決することを確認する。
1. 旧文書へのリンクが残っていないことを確認してから、旧文書を削除する。

## 書式とリンクの規則

- README の先頭は `#` 見出しとし、内容の区分には `##` 見出しを使用する。
- リンク先は、リンクを置く README からの相対パスで記述する。
- リンクだけを並べる行の末尾には半角スペースを2つ付け、Markdown 上で改行する。
- `Achievement` は親の `Subject` へ、`Evidence`・`Todo`・`Schema` は対応する親文書へ、`Result`・`Record` は対応する親文書へ `Back` リンクを置く。
- 1つの作業に複数の証拠や手順がある場合は、内容ごとに別のリンクと README を作成する。
- 旧文書のコードブロック、表、成功条件は、省略せず対応する移行先に残す。

## 移行完了の確認項目

- [ ] 旧文書の各見出し・表・コードブロック・チェックリストに移行先がある。
- [ ] `Subject` から必要な `Achievement` と `Schema` を辿れる。
- [ ] `Achievement` から必要な `Evidence` と `Todo` を辿れる。
- [ ] すべてのローカルリンクと `Back` リンクが解決する。
- [ ] 旧文書へのリンクが残っていない。
- [ ] 旧文書を削除しても参照切れが発生しない。
- [ ] `Record` と `Result` に、未定義の判断で内容を配置していない。
